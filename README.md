# wireless_regdb_unlocked (OpenWrt)

[Language: EN](README_EN.md)

Модифицированная регуляторная база wireless-regdb на основе https://kernel.org/pub/software/network/wireless-regdb
Назначение — генерация кастомного *неподписанного* `regulatory.db` с максимально ослабленными ограничениями для использования в OpenWrt.

> **⚠️ ВНИМАНИЕ**
>
> Проект намеренно формирует единый регуляторный профиль с ослабленными ограничениями по частотам, ширине каналов и EIRP/мощности и без обычных регуляторных флагов.
>
> Наличие частоты или мощности в создаваемой базе **не является разрешением на её использование**. Применение такой базы может нарушать местное законодательство и создавать помехи другим радиосистемам. Используйте проект только в контролируемой тестовой/лабораторной среде. Ответственность за соблюдение законодательства и последствия использования полностью лежит на пользователе.

## Быстрый старт

```bash
git clone https://github.com/4n0n4/wireless_regdb_unlocked.git
cd wireless_regdb_unlocked
chmod +x run.sh
./run.sh
# затем поместить regulatory.db в /lib/firmware/regulatory.db в своей сборке OpenWrt
# и перезагрузить роутер, чтобы новая регуляторная база была загружена
```

После замены `regulatory.db` необходимо **полностью перезагрузить роутер**. Простого перезапуска Wi‑Fi или сетевых служб может быть недостаточно, поскольку регуляторная база загружается ядром и подсистемой `cfg80211`.

После перезагрузки текущие правила можно проверить командой:

```bash
iw reg get
```

Скрипт `run.sh` выполняет:

```bash
bash update_regdb.sh
python3 db_txt_modificator.py db.txt.orig db.txt
python3 db2fw.py regulatory.db db.txt
```

В результате в корне репозитория появляется новый `regulatory.db`.

## Профиль частот и параметры

Все страны получают один общий профиль с максимально ослабленными ограничениями, выбранными для этого проекта.

> **ℹ️ ВАЖНО: аппаратная поддержка**
>
> **Наличие диапазона в `wireless-regdb` не означает, что он станет доступен на любом роутере.**
>
> `regdb` только сообщает ядру и драйверу допустимые частоты, ширины каналов и уровни мощности. Реальная доступность зависит от радиочипа, радиотракта, калибровочных данных, EEPROM/NVRAM, платы, антенн, прошивки и драйвера. Большинство обычных роутеров продолжит поддерживать только штатные диапазоны и каналы.
>
> В частности, диапазоны Sub‑GHz/HaLow, 3.65 ГГц, 4.9-5.1 ГГц, 45 ГГц и 60 ГГц требуют специализированного оборудования. Изменение `regdb` само по себе не может добавить отсутствующий радиотракт или снять аппаратные ограничения, ограничения калибровки, прошивки или драйвера.

Правила в терминах `wireless-regdb`:

```bash

  (755 - 928 @ 16), (N/A, 36), (N/A)        # Региональные Sub‑GHz-диапазоны, включая 802.11ah; сетка каналов зависит от реализации
  (2400 - 2483 @ 40), (N/A, 36), (N/A)      # 1-13 (2,4 ГГц, 802.11b/g/n/ax/be)
  (2474 - 2494 @ 20), (N/A, 36), (N/A)      # 14 (2,4 ГГц, 802.11b)
  (3655 - 3695 @ 40), (N/A, 36), (N/A)      # 131-138 (3,65 ГГц, 802.11y)
  (4910 - 4990 @ 40), (N/A, 36), (N/A)      # 184-196, 191/195, 21/25 (4,9 ГГц, Япония / службы общественной безопасности США)
  (5030 - 5090 @ 40), (N/A, 36), (N/A)      # 8/12/16 (5,0 ГГц, 802.11j, использование в Японии прекращено)
  (5150 - 5350 @ 160), (N/A, 36), (N/A)     # 36-64 (5 ГГц, 802.11a/h/n/ac/ax/be)
  (5350 - 5470 @ 80), (N/A, 36), (N/A)      # Промежуток между каналами 64 и 100; U-NII-2B; стандартных 20-МГц каналов Wi‑Fi нет

  (5730 - 5990 @ 160), (N/A, 36), (N/A)     # 149-196 (5 ГГц/5,9 ГГц; каналы 172-196 включают частотные планы ITS/802.11p)
```

### Расшифровка по диапазонам

- **Sub‑GHz, включая 802.11ah (755-928 МГц)**
  - Правило проекта задаёт единый непрерывный участок **755-928 МГц**, охватывающий несколько региональных частотных планов 802.11ah (Wi‑Fi HaLow).
  - В реальных регуляторных планах этот участок не является единым диапазоном: разрешённые полосы, номера и центральные частоты каналов различаются по регионам.
  - Единой сетки каналов для всего участка 755-928 МГц нет. Доступные частоты и ширины зависят от радиочипа, прошивки, драйвера и поддерживаемого частотного плана.
  - Макс. ширина по правилу `regdb`: **16 МГц**
  - Макс. EIRP по правилу: **36 dBm**
  - Требуется специализированный Sub‑GHz/802.11ah-радиомодуль. Обычные Wi‑Fi-чипы 2.4/5/6 ГГц этот диапазон не поддерживают.
  - Наличие этого правила не добавляет поддержку LoRa/LoRaWAN или других Sub‑GHz-технологий: они обычно используют собственное оборудование, драйверы и механизмы настройки частот.

- **2.4 ГГц**
  - **2400-2483 МГц** — каналы **1-13**, ширина до **40 МГц**
  - **2474-2494 МГц** — канал **14**, ширина до **20 МГц**
  - Макс. EIRP: **36 dBm**
  - Наличие правила не отменяет ограничений самого стандарта и драйвера. В частности, обычные реализации допускают канал 14 только в совместимых режимах, как правило 802.11b.

- **3.65 ГГц / 802.11y (3655-3695 МГц)**
  - Специализированный диапазон, связанный с реализациями 802.11y и системами широкополосного доступа.
  - Ориентировочно охватывает каналы **131-138** в соответствующих планах нумерации.
  - Макс. ширина по правилу: **40 МГц**
  - Макс. EIRP: **36 dBm**
  - Требуется отдельная поддержка радиочипом, firmware и драйвером.

- **4.9 ГГц (4910-4990 МГц)**
  - Специализированный диапазон, применявшийся, в частности, для систем public safety и некоторых региональных вариантов WLAN.
  - В разных регуляторных классах могут использоваться номера каналов **184-196**, а также другие схемы нумерации.
  - Макс. ширина по правилу: **40 МГц**
  - Макс. EIRP: **36 dBm**
  - На большинстве обычных роутеров диапазон недоступен из-за ограничений радиотракта, калибровки или драйвера.

- **5.0 ГГц / 802.11j (5030-5090 МГц)**
  - Специализированный диапазон, исторически использовавшийся некоторыми реализациями 802.11j.
  - Возможные номера каналов в соответствующем плане: **8, 12 и 16**.
  - Макс. ширина по правилу: **40 МГц**
  - Макс. EIRP: **36 dBm**
  - Поддержка встречается редко и зависит от конкретного оборудования, firmware и драйвера.

- **5 ГГц и 5.9 ГГц (5150-5990 МГц)**
  - Правила разделены на несколько блоков:
    - **5150-5350 МГц** — до **160 МГц**, включая обычный нижний диапазон каналов **36-64**
    - **5350-5470 МГц** — до **80 МГц**; промежуточный участок U‑NII‑2B между стандартными каналами **64** и **100**, не содержащий обычных назначенных 20‑МГц каналов Wi‑Fi и не поддерживаемый большинством потребительских устройств
    - **5470-5730 МГц** — до **160 МГц**, включая каналы **100-144**
    - **5730-5990 МГц** — до **160 МГц**, охватывая верхние каналы **149-196**; каналы **172-196** относятся к части диапазона 5.9 ГГц/ITS
  - Макс. EIRP: **36 dBm**
  - Ширины 80, 80+80 и 160 МГц доступны только при их поддержке чипсетом и драйвером.
  - Участки **5350-5470 МГц** и верхняя часть **5730-5990 МГц** обычно не поддерживаются потребительскими Wi‑Fi-устройствами полностью, даже если они присутствуют в `regdb`.

- **6 ГГц / Wi‑Fi 6E и Wi‑Fi 7 (5925-7125 МГц)**
  - Полный диапазон: **5925-7125 МГц**
  - 20‑МГц каналы: **1, 5, 9, …, 229, 233**
  - Wi‑Fi 6E / 802.11ax: ширина до **160 МГц**
  - Wi‑Fi 7 / 802.11be: ширина до **320 МГц**
  - Макс. EIRP по правилу: **36 dBm**
  - Фактическая доступность полного диапазона и ширины 320 МГц зависит от поколения радиочипа, firmware и драйвера.

- **45 ГГц / 802.11aj (42,39-48,33 ГГц)**
  - Миллиметровый диапазон для специализированных реализаций 802.11aj.
  - Частотный план и нумерация каналов зависят от конкретной реализации.
  - Макс. ширина по правилу: **1080 МГц**
  - Макс. EIRP: **44 dBm**
  - Требуется специализированное mmWave-оборудование; обычные Wi‑Fi-радиомодули этот диапазон не поддерживают.

- **60 ГГц / 802.11ad и 802.11ay (57-71 ГГц)**
  - Миллиметровый диапазон: **57000-71000 МГц**
  - Базовый план DMG включает каналы **1-6** шириной **2,16 ГГц**.
  - В 802.11ay также предусмотрены расширенные конфигурации EDMG и объединение каналов; их доступность зависит от оборудования и реализации.
  - Макс. ширина по правилу: **2160 МГц**
  - Макс. EIRP: **44 dBm**
  - Требуется отдельный 60‑ГГц радиомодуль и соответствующая антенная система.

### Что именно изменяет этот профиль

Для всех перечисленных диапазонов заданы выбранные проектом максимальные ширины каналов и значения EIRP. Также для стран используется единый набор правил без обычных региональных различий.

Снято или не задаётся:

- различие профилей по странам;
- ограничения indoor/outdoor;
- флаги DFS и TPC;
- другие регуляторные флаги `wireless-regdb`.

При этом профиль **не снимает**:

- аппаратные ограничения радиочипа и RF-тракта;
- ограничения EEPROM, NVRAM и калибровочных данных;
- ограничения firmware и драйвера;
- ограничения поддерживаемых стандартов и режимов;
- требования законодательства страны, в которой эксплуатируется устройство.

## Особенности канала 14 (2.4 ГГц)

Поддержка канала 14 реализована в рамках стандарта: только 802.11b и ширина 20 МГц.

Требования:

- Режим: **802.11b / Legacy с разрешёнными скоростями 802.11b**
- Ширина: **20 МГц**

В LuCI / настройках Wi‑Fi:

1. Включить:

   > **Allow legacy 802.11b rates**

2. Отключить:

   > **Force 40MHz mode**

Номинальная PHY-скорость на 14‑м канале ограничена режимами 802.11b и составляет до 11 Мбит/с; реальная полезная пропускная способность будет ниже.

## Состав репозитория

- **`regulatory.db`** — пересобранный бинарный файл БД (перезаписывается скриптом).
- **`db.txt.orig`** — оригинальный текстовый дамп regdb (может быть автоматически обновлён из https://kernel.org/pub/software/network/wireless-regdb).
- **`db.txt`** — модифицированный дамп, генерируется автоматически (перезаписывается).
- **`db_txt_modificator.py`** — модификатор `db.txt`:
  - удаляет комментарии;
  - для каждой страны (`country XX:`) подставляет единый набор частотных диапазонов/мощностей;
  - сохраняет блок `wmmrule ETSI:` без комментариев.
- **`dbparse.py`** — парсер текстового `db.txt` (из upstream wireless-regdb).
- **`db2fw.py`** — модифицированный сборщик `regulatory.db`:
  - убрана зависимость от библиотеки подписи;
  - формирует *неподписанный* `regulatory.db`, совместимый с OpenWrt;
  - структура файла соответствует стандартному `regulatory.db`, поле подписи отсутствует.
- **`run.sh`** — обёртка для запуска полного цикла:
  - обновление исходной базы (через `update_regdb.sh`);
  - генерация модифицированного `db.txt`;
  - сборка `regulatory.db`.
- **`update_regdb.sh`** — скрипт обновления исходной базы:
  - при необходимости скачивает свежий `db.txt.orig` из https://kernel.org/pub/software/network/wireless-regdb; 
  - обновляет файл `version` с информацией о использованной версии.
- **`version`** — текстовый файл с версией/датой исходного wireless-regdb, из которой взят `db.txt.orig`.

## Как это работает

1. Используется исходный `db.txt.orig` (дамп стандартной регуляторной БД). При запуске `run.sh` он может быть автоматически обновлён через `update_regdb.sh`.
2. `db_txt_modificator.py`:
   - оставляет для каждой страны только заголовок `country CC:`;
   - вставляет предопределённый набор диапазонов/мощностей (`TEMPLATE_LINES`);
   - результат — единый максимально «разлоченный» профиль для всех стран.
3. `db2fw.py`:
   - парсит модифицированный `db.txt`;
   - формирует бинарный `regulatory.db` без подписи.

## Требования

- Python 3 (тестировалось на версиях 3.x);
- стандартная среда Linux (bash, coreutils).

Дополнительные библиотеки Python (`pip install`) не требуются.

## Область применения и ограничения

- Проект ориентирован на OpenWrt, где проверка подписи `regulatory.db` отключена.
- На системах, где проверка подписи обязательна, данный файл не будет работать без:
  - патча ядра; или
  - собственной системы подписи и поддержки соответствующего ключа в ядре.
