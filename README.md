# wireless_regdb_unlocked (OpenWrt)

[Language: EN](README_EN.md)

Модифицированная регуляторная база wireless-regdb на основе https://kernel.org/pub/software/network/wireless-regdb
Назначение — генерация кастомного *неподписанного* `regulatory.db` с максимально ослабленными ограничениями для использования в OpenWrt.

> ⚠️ **ВНИМАНИЕ:** проект сознательно снимает ограничения по используемым частотам, ширине каналов и EIRP/мощности и игнорирует регуляторные флаги.
> Использование может нарушать местное законодательство. Вся ответственность лежит на пользователе.

---

## Быстрый старт

```bash
git clone https://github.com/4n0n4/wireless_regdb_unlocked.git
cd wireless_regdb_unlocked
chmod +x run.sh
./run.sh
# затем поместить regulatory.db в /lib/firmware/regulatory.db в своей сборке OpenWrt
```

Скрипт `run.sh` выполняет:

```bash
bash update_regdb.sh
python3 db_txt_modificator.py db.txt.orig db.txt
python3 db2fw.py regulatory.db db.txt
```

В результате в корне репозитория появляется новый `regulatory.db`.

## Профиль частот и параметры

Все страны получают один и тот же профиль с максимально ослабленными (для этого проекта) ограничениями.

Диапазоны и параметры (в терминах wireless-regdb):

```text
(755 - 928 @ 16), (36)
(2400 - 2483.5 @ 40), (36)
(2474 - 2494 @ 20), (36)
(4910 - 4990 @ 40), (36)
(5150 - 5350 @ 160), (36)
(5470 - 5730 @ 160), (36)
(5730 - 5895 @ 160), (36)
(5925 - 7125 @ 320), (36)
(57000 - 71000 @ 2160), (44)
```

Расшифровка по диапазонам:

- **Sub‑GHz (755–928 МГц)**
  - Обобщённые sub‑GHz / IoT‑диапазоны (фактическое использование зависит от региона и чипсета)
  - Макс. ширина канала (по правилу regdb): **16 МГц**
  - Макс. EIRP: **36 dBm**

- **2.4 ГГц**
  - **2400–2483.5 МГц** — каналы **1–13**, ширина до **40 МГц**, до **36 dBm EIRP**
  - **2474–2494 МГц** — канал **14**, ширина **20 МГц**, до **36 dBm EIRP**
    (стандартное ограничение: 14‑й канал только для 802.11b, см. раздел про канал 14)

- **4.9 ГГц (4910–4990 МГц)**
  - Спецдиапазон «4.9 GHz public safety» (работает только при поддержке со стороны железа и драйвера)
  - Примеры номеров каналов в некоторых регуляторных классах: **184–196** (20/40 МГц)
  - Макс. ширина канала: **40 МГц**
  - Макс. EIRP: **36 dBm**

- **5 ГГц**
  - Частотный диапазон (по правилам regdb): **5150–5895 МГц**
  - Каналы (20 МГц):
    - **36–64** — нижний диапазон 5 ГГц (≈ 5150–5350 МГц)
    - **100–144** — диапазон, который в стандартных профилях обычно помечен как DFS (≈ 5470–5730 МГц)
    - **149–177** — верхний диапазон 5 ГГц (≈ 5730–5895 МГц)
  - Макс. ширина канала: до **160 МГц** (80, 80+80, 160 — при поддержке)
  - Макс. EIRP: **36 dBm**

- **6 ГГц (Wi‑Fi 6E / Wi‑Fi 7, 5925–7125 МГц)**
  - Полный диапазон 6 ГГц: нижний, средний и верхний блоки
  - Частотный диапазон: **5925–7125 МГц**
  - 20‑МГц каналы: **1, 5, 9, …, 229, 233**
    (точная сетка и доступность зависят от региона и прошивки)
  - Типичная поддержка стандартов:
    - Wi‑Fi 6E (802.11ax): ширина каналов до **160 МГц**
    - Wi‑Fi 7 (802.11be): ширина каналов до **320 МГц**
  - Макс. EIRP (по правилу regdb): **36 dBm**

- **60 ГГц / мм‑диапазон (57–71 ГГц)**
  - Диапазоны 802.11ad/ay
  - Частотный диапазон (по правилу regdb): **57000–71000 МГц**
  - Разбиение на каналы зависит от реализации (обычно несколько широких каналов по 2.16 ГГц)
  - Макс. ширина канала (по правилу): **2160 МГц**
  - Макс. EIRP: **44 dBm**

Во всех диапазонах заданы максимально высокие значения ширины каналов и EIRP, выбранные для этого шаблона regdb. Фактически доступные каналы, ширины и режимы зависят от конкретного чипсета, прошивки и драйвера.

Снято/игнорируется:

- различие профилей по странам;
- ограничения по indoor/outdoor;
- флаги DFS, TPC и другие регуляторные флаги.

## Особенности канала 14 (2.4 ГГц)

Поддержка канала 14 реализована в рамках стандарта: только 802.11b и ширина 20 МГц.

Требования:

- Режим: **Legacy (802.11b/g)**
- Ширина: **20 MHz**

В LuCI / настройках Wi‑Fi:

1. Включить:

   > **Allow legacy 802.11b rates**

2. Отключить:

   > **Force 40MHz mode**

Реальный полезный битрейт на 14‑м канале ограничен скоростями 802.11b (до ~11 Мбит/с) и подходит только для тестовых или низкоскоростных сценариев.

## Состав репозитория

- **`regulatory.db`** — пересобранный бинарный файл БД (перезаписывается скриптом).
- **`db.txt.orig`** — оригинальный текстовый дамп regdb (может быть автоматически обновлён из https://kernel.org/pub/software/network/wireless-regdb).
- **`db.txt`** — модифицированный дамп, генерируется автоматически (перезаписывается).
- **`db_txt_modificator.py`** — модификатор `db.txt`:
  - удаляет комментарии;
  - для каждой страны (`country XX:`) подставляет единый набор частотных диапазонов/мощностей;
  - сохраняет блок `wmmrule ETSI:` без комментариев.
- **`dbparse.py`** — парсер текстового `db.txt` (из upstream wireless-regdb).
- **`db2fw.py`** — модифицированный сборщик `regulatory.db`:
  - убрана зависимость от библиотеки подписи;
  - формирует *неподписанный* `regulatory.db`, совместимый с OpenWrt;
  - структура файла соответствует стандартному `regulatory.db`, поле подписи отсутствует.
- **`run.sh`** — обёртка для запуска полного цикла:
  - обновление исходной базы (через `update_regdb.sh`);
  - генерация модифицированного `db.txt`;
  - сборка `regulatory.db`.
- **`update_regdb.sh`** — скрипт обновления исходной базы:
  - при необходимости скачивает свежий `db.txt.orig` из https://kernel.org/pub/software/network/wireless-regdb; 
  - обновляет файл `version` с информацией о использованной версии.
- **`version`** — текстовый файл с версией/датой исходного wireless-regdb, из которой взят `db.txt.orig`.

## Как это работает

1. Используется исходный `db.txt.orig` (дамп стандартной регуляторной БД). При запуске `run.sh` он может быть автоматически обновлён через `update_regdb.sh`.
2. `db_txt_modificator.py`:
   - оставляет для каждой страны только заголовок `country CC:`;
   - вставляет предопределённый набор диапазонов/мощностей (`TEMPLATE_LINES`);
   - результат — единый максимально «разлоченный» профиль для всех стран.
3. `db2fw.py`:
   - парсит модифицированный `db.txt`;
   - формирует бинарный `regulatory.db` без подписи.

## Требования

- Python 3 (тестировалось на версиях 3.x);
- стандартная среда Linux (bash, coreutils).

Дополнительные библиотеки Python (`pip install`) не требуются.

---

## Область применения и ограничения

- Проект ориентирован на OpenWrt, где проверка подписи `regulatory.db` отключена.
- На системах, где проверка подписи обязательна, данный файл работать не будет без:
  - патча ядра, или
  - собственной системы подписи и поддержки соответствующего ключа в ядре.

Использование ограничивайте тестовой/лабораторной средой и учитывайте требования местного регулятора.
